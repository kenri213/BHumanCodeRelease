## 本轮恢复逻辑

1. 正式Match中，普通遥控`REMOVE`进入Stand保持，不自动卸力退出，也不继续旧杆量或自动比赛。
2. X、F1、非法轴、空消息以及原有身体、相机、IMU故障保护仍保留；不能解读为任何故障都会保持站立。
3. RB+A只在新鲜合法INITIAL、READY或PLAYING中允许；SET、FINISHED、未知状态、STOP、罚下及无效时间戳拒绝。
4. 非INITIAL只允许真实稳定卧姿的身体恢复；不能借RB+A给直立机器人授予走踢权限。
5. 保留完整长按、实际Prepare插值、姿态稳定和原始8秒总期限。
   短时断包不产生新动作；同一已接受意图只可在恢复新鲜包后有界刷新150毫秒Prepare令牌。
6. 比赛中人工恢复完成后先Stand；真实Stand持续至少300毫秒才丢弃站稳前所有遥控证据。
   随后必须重新松键回中，再LT+选择遥控或LT-选择自动，不能刚起身就自动冲场。
7. 正常比赛的原生自动倒地恢复仍走原GetUp链路，不修改起身模型、基础步态模型或PD。

原有新鲜真实F1授权、唯一来源裁判接收、无固定比赛运行时限、启动失败留首错、
有界服务等待、完整输入路由恢复继续保留。启动器新增十阶段耗时输出，但没有凭空缩短硬件初始化。

## 离线回归与构建

在本仓库根目录，使用已有可用的Python和C++编译器：

```bash
python3 -m unittest discover -s Tests/K1Commissioning -p 'test_*.py'
python3 -m unittest discover -s Tests/K1RealSense -p 'test_*.py'
(cd Deploy/K1Match996 && python3 -m unittest -v test_match_control)
```

ARM64构建继续使用仓库K1交叉工具链和官方依赖，隔离构建目录置于仓库外。
`Deploy/K1Match996/mode_query/build.sh`接受仓库路径参数；其历史默认开发机路径不具有跨机器可移植性。
应显式传入当前仓库绝对路径，或为其CMake传入`BHUMAN_ROOT`，不要照搬开发机个人路径。

`Tools/K1Commissioning/check_match_release.py`核验同版ELF、启动器和资源，但离线通过不代表身体已验收。
任何新编译产物须绑定新的完整源码/配置/工具链哈希和测试记录后，才进入独立部署流程。

## 现场边界与回滚

文件同步不自动启动身体、不刷固件、不改模型、PD、密码或网络。
X/F1/stop可能卸力，站立机器人可能倒下，不是自动坐下。
源码回退与机器人文件/输入路由回滚是两种操作；Git回退不会自动恢复机器人的已安装文件。
机器人回滚必须使用该台该轮已核验的备份manifest，并确认APP停止及输入路由已恢复。
