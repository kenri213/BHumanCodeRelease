# 996 / 987：比赛中实体STAND退场与WALK回场

本分支基于996实装37a2对应的`35b4d3cee3e8f3d8e8774a01f73cefde44ee0fd4`，
只补人工Pickup的控制通路，并纳入987已有的独立身份入口。
模型、PD、速度、相机推理、定位与球队攻防策略不变，不混入其它机器人的后续保护候选。

## 为什么原版不响应

996原适配将实体STAND进入Prepare与起身恢复共用门禁：要求手柄有效、合法裁判包，
并且处于INITIAL或稳定卧姿。READY/PLAY中的正常直立机器人因此被挡住；已经罚下或手柄掉线时也会被挡。
987继承了这段逻辑。实体键映射没有删除；修的是退出比赛与重新参赛权限混用。

## 现在的操作

1. **退场：先按官方要求承托提手，再按实体STAND。**
   已完成本轮F1授权、无真实身体故障、处于正常Stand/Walk时，进入原生PRE并锁定。
   不要求全场切INITIAL，不依赖手柄在线，也不会因处罚或裁判包变化自行恢复比赛。
2. **按裁判允许的位置、方向放回。**
   PRE是不平衡准备姿态，不是卸力或自动坐下；无人承托可能摔倒。
   本修复不改变回场定位先验，不能任意摆放后指望白线自动消除半场歧义。
3. **身体直立后，新按住实体WALK超过2秒。**
   需实际PRE插值已满2秒、真实IMU直立稳定至少300ms；先进入原生Stand，
   再以真实Stand反馈稳定至少300ms确认。不是仅按计时器猜已经站稳。
4. **裁判当时合法，才能交回自动比赛。**
   同一次WALK按下时与后续放行时均需真实新鲜合法裁判信息、已解除罚下、非STOP/SET。
   满足时同一次明确操作可交回自动，无需RB+Y或额外LT组合键。
   若按WALK时仍非法，只恢复/保持Stand和Pickup锁；之后解除处罚，必须先松开再新长按WALK。

STAND会撤销旧起身票、旧初始自动交权和旧遥控证据。回场不会续旧杆量；
重新使用遥控必须有真实新回中样本后再作新的接管选择。

正常回场使用直立WALK流程。若人工Pickup锁中放回时仍为稳定卧姿，必须有合法新鲜裁判信息和
原有Gate确认的新RB+A，才交回旧Prepare/GetUp链；旧持键或罚下状态不能逃出Pickup锁。
该卧姿出口起身后仍先Stand，再按原有新回中/LT操作交权，不自动接回足球。
真实Fall/GetUp/PlayDead不能被强行切PRE，异常恢复后保留人工锁，不借此放开足球动作。
F1、X和真实身体故障保护始终优先，F1/X停止可能失去支撑。

## 验证与发布边界

- 新的SDK无关测试直接验证生产Gate与接线，包含READY/PLAY/罚下退场、非法WALK不续票、
  原生相位、真实Stand反馈、CABSL生命周期和旧遥控证据隔离。
- 从新目录完整构建ARM64目标；独立复核修正后的源码还需重新编译，冻结后Ninja无工作才交付。
- 每机使用自己的controller、路由core、专属Config与SDK，备份旧版后仅文件级更新。
  987的模型、engine及运行库未变时仅重绑APP缓存证明，不复制别机缓存、不重预热。
- 文件安装不启动身体程序；物理STAND/PRE/WALK、承托与定位方向、真实比赛仍须现场验证。
- Git分支只提交源码、测试与说明，不新增ELF、私钥、密码、系统备份或机器生成的缓存。
  仓库历史缓存也不应作为其它机器的可用缓存分发。

可观察诊断包括`PHYSICAL_PICKUP entered_PRE`、`PHYSICAL_PICKUP AUTO_RELEASE`。
看到按键日志不等于实际已进入PRE；搬运前确认真实模式，不能只凭一行请求就放开承托。

回滚分两层：Git源码回退不改变机器人；真机须在安全停止、原路由恢复后，
按本机`pickup_stand_backup_20261024_01`中的原始运行元数据恢复同版APP/controller/说明和缓存证明。
