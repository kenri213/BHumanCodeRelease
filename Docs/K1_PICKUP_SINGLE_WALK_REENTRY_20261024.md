# Pickup回场v2：一次长WALK，站稳等裁判解罚

本轮从已发布`e7bb82507c8e7b40fc2cea9a48d65abf40992a6e`继续，仅修改人工Pickup回场请求的生命周期。
共享源码具备996/987入口，但本轮只部署、测试987；不据此声称996实装已更新。
不改模型、PD、定位、比赛策略、裁判白名单、手柄映射或首启F1/RB+A流程。

## 本轮要解决的问题

v1在WALK按下时把“当时是否已解罚”永久锁存。若先长WALK站稳、再在裁判机真正解除该球员处罚，
仍须第二次长WALK，增加了无必要的操作。v2将“操作者已正确放回”与“裁判允许回场”分开。

## 操作顺序

1. 已授权且正常Stand/Walk时，先承托提手，再按实体STAND进入原生PRE人工锁。PRE没有平衡能力，须持续承托。
2. 按裁判允许的位置和朝向直立放回，松开旧按键，新长按实体WALK超过2秒。此时可以仍被罚下。
3. 真实PRE插值和直立稳定满足后转Stand，等待真实Stand稳定至少300ms。
4. 裁判机真正把本队、本球员的处罚清为`NONE`；收到新鲜合法包后交回自动。不再要求第二次长WALK。

“取消Pickup工具/倒计时结束”不必然代表球员已解罚，机器人只认实际UDP处罚字段，不擅自清罚。
回场位置与朝向仍须正确；本轮不增加视觉定位验收，也不把对称白线当成半场证明。

## 保留的保护

- 新WALK必须在新鲜、队号/球员匹配、允许比赛状态且非STOP的裁判上下文开始；仅本机罚下不阻止建立放回请求。
- 长按尚未完成时丢失该上下文，不得后来借旧持键补出待票；身体仍可按原安全条件恢复Stand。
- 只有完整明确长按完成后，才存在待解罚请求。其后的STOP/SET或裁判包间隙仅暂停自动；恢复合法新鲜信息前绝不回场。
- 新鲜FINISHED或未知主状态、本队/本球员身份失配会撤销待票，不能跨比赛结束继续沿用；不是所有非法状态都无限等待。
- 已完成请求不设任意等待秒数，不会因正常处罚较久再次要求长按；实际Stand与直立证据须实时、连续满足。
- F1/X、真实身体故障、授权/epoch或手柄代变化、新STAND、原生倒地/起身、乱序或行为被抢占等仍撤销旧请求。
- 手柄断联代数不自动更新；最终交权仍通过同代CAS，不能覆盖并发新断联。旧摇杆/旧LT不接管。
- 真实Fall/GetUp/PlayDead按原生相位处理，不强插PRE。锁中稳定卧姿仍仅经合法新RB+A回旧恢复链，起身后先Stand并按原新回中/LT交权。
